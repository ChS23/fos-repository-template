# Инструменты репозитория

Собственные программные средства, разработанные для сопровождения фонда оценочных средств. Все инструменты не требуют внешних сервисов и запускаются локально либо в системе непрерывной интеграции.

| Инструмент | Назначение | Кто применяет |
|---|---|---|
| [`validate_fos.py`](validate_fos.py) | проверка внутренней согласованности ФОС | преподаватель, CI |
| [`generate_dataset.py`](generate_dataset.py) | генерация вариантов данных и модели для КИМ-4.5 | преподаватель |
| [`ktu_calc.py`](ktu_calc.py) | расчёт коэффициента трудового участия по формам взаимооценки | преподаватель |
| [`../M2-requirements/attachments/ci-check.py`](../M2-requirements/attachments/ci-check.py) | формальная проверка спецификации требований обучающегося | обучающийся, CI |

## Валидатор ФОС

Проверяет восемь групп условий: разрешимость относительных ссылок, отсутствие незаполненных маркеров, равенство суммы баллов рубрики каждого КИМ ста баллам, равенство суммы весов оценочных средств ста процентам, соответствие индикаторов паспорта КИМ и README модуля, покрытие индикаторов модели измерения контрольно-измерительными материалами, единообразие шкалы перевода и согласованность часов рабочей программы.

```bash
python tools/validate_fos.py .
```

Код возврата 0 — нарушений нет, 1 — нарушения выведены списком. Валидатор запускается автоматически при каждом изменении репозитория (см. `.github/workflows/validate.yml`).

Инструмент решает практическую задачу сопровождения: ФОС состоит из нескольких десятков связанных документов, и при правке одного из них согласованность нарушается незаметно — например, изменение веса оценочного средства перестаёт соответствовать рубрике, а переименование КИМ оставляет висячие ссылки.

## Генератор данных для КИМ-4.5

Формирует синтетические данные продаж, обучает модель и рассчитывает метрики. Вид намеренного дефекта задаётся параметром, что позволяет готовить разные варианты задания и обновлять их ежегодно.

```bash
uv venv --python 3.12 && uv pip install numpy pandas scikit-learn
python tools/generate_dataset.py --defect drift --seed 20260717 --out out/
```

| Значение `--defect` | Поведение модели |
|---|---|
| `none` | контрольный вариант без дефекта |
| `drift` | дрейф концепции: качество на свежем срезе существенно хуже, чем на отложенной выборке |
| `subgroup` | перекос по подгруппе: средняя метрика в норме, отдельная категория прогнозируется хуже |
| `leakage` | утечка целевой переменной через признак, недоступный на момент прогноза |
| `shift` | смещение обучающей выборки: обучение на периоде без промоакций |

Отчёт команды разработки и описание заложенного дефекта готовятся преподавателем и в выгрузку не входят: они относятся к закрытым материалам.

## Расчёт коэффициента трудового участия

Реализует методику раздела 9 [проектной работы](../Project/README.md): взаимооценка участников (вес 40 %), оценка зоны ответственности (40 %) и объективные следы работы (20 %) сводятся в коэффициент, ограниченный диапазоном 0,8–1,2.

```bash
python tools/ktu_calc.py peer-review/team-01.json
```

Инструмент отбрасывает крайние оценки при трёх и более оценивающих, ограничивает коэффициент значением 1,0 при отсутствии индивидуальной защиты и отдельно выводит участников, по которым расхождение между взаимооценкой и оценкой преподавателя превышает допустимое.

## Требования к окружению

`validate_fos.py` и `ktu_calc.py` используют только стандартную библиотеку Python 3.10+. `generate_dataset.py` требует `numpy`, `pandas` и `scikit-learn`.
