# Фонд оценочных средств по дисциплине «Системная инженерия для систем искусственного интеллекта»

Репозиторий содержит фонд оценочных средств (ФОС) по дисциплине «Системная инженерия для систем искусственного интеллекта». Здесь объединены рабочая программа дисциплины, модель измерения результатов обучения, контрольно-измерительные материалы (КИМ), критерии оценивания, методические рекомендации и используемые образовательные ресурсы. Результаты обучения связаны с компетентностно-ролевой моделью в области искусственного интеллекта (КРМ версии 3.0).

## 1. О дисциплине

**Цель дисциплины.** Сформировать системное мышление, навыки анализа сложных инженерных задач, разработки проектной документации и применения методов системной инженерии для программно-аппаратных комплексов, а также компетенции в проектировании, разработке и управлении жизненным циклом сложных систем с интеграцией компонентов искусственного интеллекта.

**Основные задачи.** Освоение методов анализа бизнес-проблем и оценки целесообразности применения ИИ; разработка технической документации на системы ИИ; управление требованиями и архитектурное проектирование; обоснование выбора вычислительной платформы; оценка рисков недетерминированного поведения моделей и угроз безопасности; управление качеством данных, правовыми и этическими аспектами внедрения ИИ.

**Структура и содержание.** Дисциплина состоит из четырёх модулей: «Введение в системную инженерию», «Управление требованиями», «Архитектура систем», «Обеспечение качества, безопасность и сопровождение систем искусственного интеллекта». Обучение включает лекции, практические занятия, лабораторные работы, деловые игры и проектную работу и завершается экзаменом с защитой проекта. Объём — 144 академических часа (4 зачётные единицы), 5 семестр.

**Пререквизиты.** Программирование (индикатор PL-1.1, уровень С), Управление данными (BD-3.1, Б), Основы искусственного интеллекта (ML-2.1, Б).

**Целевые профессиональные роли.** AI-PM (менеджер проектов в области искусственного интеллекта) и ML Engineer (инженер машинного обучения).

**Планируемые результаты обучения.** По завершении дисциплины обучающийся способен:

- **РО-1.** анализировать бизнес-проблему и оценивать целесообразность применения ИИ (LC-1.1);
- **РО-2.** разрабатывать требования и техническую документацию на систему ИИ с обеспечением трассируемости (LC-1.2, LC-1.3, ОПК-4.1);
- **РО-3.** проектировать архитектуру системы ИИ с обоснованием технологических решений (LC-3.1);
- **РО-4.** планировать и контролировать процессы жизненного цикла ИИ-продукта (LC-4.1);
- **РО-5.** организовывать верификацию, валидацию и сопровождение систем ИИ (LC-3.1, LC-4.1);
- **РО-6.** обосновывать выбор вычислительной платформы под ограничения программно-аппаратного комплекса (HPC-1.1, HPC-2.1);
- **РО-7.** выявлять угрозы безопасности системы ИИ, оценивать защищённость и проектировать меры защиты (AI S-1.1, AI S-2.1, AI S-3.2).

Полное описание приведено в [РПД](docs/rpd.md).

### 2.2. Виды оценочных средств

Формы контроля намеренно разнородны: документационные артефакты дополнены аналитическими, устными и взаимными формами, поскольку проверка только текстового результата в условиях доступности генеративных моделей недостаточна.

| Вид | Где применяется | Что проверяет |
|---|---|---|
| Лабораторная работа с артефактом | КИМ-1.5, КИМ-2.5, КИМ-3.5, КИМ-4.5 | способность разработать проектный артефакт |
| Инспекция сгенерированного артефакта | КИМ-2.5, КИМ-3.5 | способность найти дефекты в чужом (машинном) результате |
| Расчётное задание | КИМ-3.5 (вычислительная платформа) | инженерный расчёт под ограничения |
| Программная реализация проверок | КИМ-4.5 | построение контура верификации кодом |
| Деловая игра | КИМ-4.5 (защита решения перед командой разработки) | способность отстоять инженерное решение |
| Анализ влияния изменения | КИМ-2.5, КИМ-3.5, проектная работа | понимание последствий по собственной трассируемости |
| Проектная работа в команде | проект | интеграция результатов, работа с партнёром |
| Взаимное рецензирование и взаимооценка | проект | качество рецензирования, вклад в команду |
| Устная защита | все оценочные средства | понимание и авторство результата |
| Теоретический экзамен по билетам | экзамен | владение понятийным аппаратом и стандартами |

|---|---|
| `validate_fos.py` | проверка внутренней согласованности ФОС: ссылки, суммы баллов рубрик, веса, покрытие индикаторов, единообразие шкал, часы РПД. Запускается автоматически при каждом изменении |
| `generate_dataset.py` | генерация вариантов данных и модели для КИМ-4.5 с параметризуемым видом дефекта |
| `ktu_calc.py` | расчёт коэффициента трудового участия по формам взаимооценки |
| `ci-check.py` | формальная проверка спецификации требований обучающегося перед сдачей |

Первый инструмент решает задачу, которая иначе ложится на преподавателя вручную: ФОС состоит из нескольких десятков связанных документов, и правка одного из них нарушает согласованность незаметно.

### 6.2. Адаптация и переиспользование

Дисциплина построена на сквозном кейсе прогнозирования спроса, однако структура ФОС от предметной области не зависит. Для переноса на другую область достаточно заменить описание бизнес-контекста ([`M1-introduction/attachments/business-context.md`](M1-introduction/attachments/business-context.md)) и данные; формулировки заданий, критерии и рубрики сохраняются.

Отдельно переиспользуемы: шаблоны артефактов (требование, ADR, ПМИ, карточка модели, модель угроз), модель оценивания в условиях доступности генеративных моделей, инструменты из `tools/`, форма взаимооценки вклада. Модули 2–4 могут применяться независимо в курсах по управлению требованиями, архитектуре ИИ-систем и MLOps.

## 7. Использование генеративного искусственного интеллекта

Дисциплина готовит специалистов, чья профессиональная деятельность предполагает применение инструментов искусственного интеллекта. Использование генеративных моделей при выполнении заданий разрешено и является обязательным предметом декларирования. Оценивается не факт использования, а качество контроля над результатом: обоснованность решений, проверка фактов и способность защитить работу. Правила приведены в [методических указаниях обучающимся](methodical-guidelines/students/README.md) и в каждом КИМ.
